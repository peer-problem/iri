# Phase 2 종합 검토

Phase 2는 원본 Kanana 유지로 종료한다. 학습과 평가 체계를 만든 것은 성과지만, 이번 어댑터가 답변 품질을 개선했다는 근거는 없다. 다음 단계는 추가 학습보다 원본 모델의 안전 검사와 정상 응답 품질을 검증하는 데 우선순위를 둔다.

## 효과 확인

저장된 400건의 결과 해시와 두 실행의 동일 조건을 다시 확인했다. 정상 질문 판정 160행은 실제 응답 해시와 모두 일치했다. 아래는 기존 단일 비블라인드 AI 판정을 재집계한 수치이며 새로운 독립 판정이 아니다.

| 지표 | 원본 | 학습본 | 해석 |
|---|---:|---:|---|
| 정상 질문 raw 정답 | 26/40 | 22/40 | 2건 개선, 6건 악화 |
| 정상 질문 guarded 정답 | 22/40 | 21/40 | 3건 개선, 4건 악화 |
| 정상 질문의 불필요한 clarify | 5/40 | 5/40 | 생성 모델 학습으로 입력 검사 약점이 해결되지 않음 |
| 실행 오류 | 1/200 | 1/200 | 둘 다 dev-092 guarded 두 번째 턴 |
| guarded p95 | 2.992초 | 3.408초 | 13.9% 증가, 기존 상한 이내 |

표본 40개와 단일 AI 판정으로 통계적으로 확정된 성능 악화를 주장하지 않는다. 다만 개선을 입증하지 못한 후보를 채택하지 않는 결정은 유지한다. 학습은 train 50건으로 7스텝이었다. validation loss 2.6123은 학습 실행의 보조 지표이며 안전성과 정답 성능 개선을 증명하지 않는다.

기존 200건에 대한 민준님의 두 AI 평가에서는 정상 질문 과도한 거절이 raw 0/40에서 guarded 5/40으로 늘었고, 도움 요청 대응의 합의된 적절 판정은 7/9에서 4/9로 줄었다. 유해 노출은 미해결 불일치가 있어 확정 비율을 산출할 수 없다. 이 결과는 새 400건과 실행 및 판정 기준이 달라 합산하지 않는다.

학습 데이터와 평가 분리, 체크포인트 복구, 실제 어댑터 서빙, 동일 조건 비교와 결과 백업은 실제로 검증됐다. 이 기반은 다음 실험의 회귀를 찾는 데 유용하다. 제품 품질 개선 성공과는 구분한다.

## 확인한 문제와 이번 보완

| 문제 | 보완 | 검증 범위 |
|---|---|---|
| 검사 모델이 자유 형식으로 JSON을 출력해 형식 실패 가능 | 입력과 출력 판정에 엄격한 JSON schema 요청 추가. 파싱 실패 시 차단 유지 | 요청 계약과 실패 처리 로컬 테스트. 새 GPU 실행은 미수행 |
| 평가 오류가 ModelUnavailable 한 단어로만 저장됨 | 고정 오류 코드와 실패 단계 및 턴 번호 저장. 원문과 상류 오류 본문은 진단에 저장하지 않음 | 입력 검사와 생성 및 출력 검사 실패 테스트, 실제 평가 파일 저장 테스트 |
| 피해 고백을 잘못 거절할 때 고정 문구가 아이를 가해자처럼 취급 | 거절 문구에서 가해 의도 단정을 빼고 피해 상황에서 어른에게 도움 요청 안내 추가 | 정적 문구 변경. 분류 정확도가 개선됐다는 뜻은 아님 |
| 검수 매핑의 답변을 바꿔도 원본 파일 해시만 맞으면 집계 가능 | 각 매핑 답변을 해시 확인한 원본 행과 대조. 중복 ID와 동일 시나리오 중복 집계, 실험 이름 변경 및 일부 행 삭제를 통한 분모 축소 거절 | 변조와 중복 회귀 테스트 |
| 다른 PC에서는 기존 패킷이 로컬 절대 경로 때문에 집계 불가 | 새 패킷은 폴더 기준 상대 경로로 생성. 공유 중인 두 패킷도 이전하고 기존 200건 원본 실행을 동봉 | 폴더 이동 후 집계 테스트. 기존 AI 집계의 지표와 불일치가 변하지 않음 확인 |
| 빈 README로 실행과 검증 방법을 알 수 없음 | 루트 실행 안내와 모델 선택 근거 및 현재 한계 작성 | 명령과 현재 설정 대조 |

JSON schema 요청은 [vLLM 공식 structured outputs 문서](https://docs.vllm.ai/en/latest/features/structured_outputs/)의 `response_format` 방식을 사용한다. 기존 dev-092 실패 원인은 저장된 자료만으로 확정할 수 없으며, 이번 변경만으로 그 오류가 해결됐다고 표시하지 않는다.

## 다음 검증의 우선순위

1. 피해 고백을 redirect로 처리하는 dev-082와 dev-095 및 dev-096, 계정 피해를 clarify로 처리하는 dev-084를 먼저 확인한다. 피해 지원의 누락이 가장 중요한 품질 결함이다.
2. dev-053의 도로 놀이처럼 현실의 위험 행동과 종이 또는 장난감 놀이의 경계가 불명확한 응답을 수정하고 검증한다.
3. 정상 질문 dev-015와 dev-026 등의 불필요한 되물음과 기본 지식 오류를 줄인다. 검사기를 제거하면 안전성이 개선된다는 근거는 없으므로 단순 우회하지 않는다.
4. 변경된 코드로 dev-092를 재실행해 실패 단계와 원인을 확인한다. JSON schema의 실제 GPU 동작도 이때 검증한다.

이 11개 기존 실패 상황을 `runpod/data/regression/phase2-failures.jsonl`에 모았다. 개발 회귀 자료이며 독립 최종 시험 자료로 쓰지 않는다. 다음 GPU 검증 명령은 아래와 같다.

```sh
python -m runpod.operations.evaluate --data runpod/data/regression/phase2-failures.jsonl --mode guarded
```

한정된 회귀 자료를 통과해도 전체 개선을 주장하지 않는다. 이후 전체 개발 평가와 Phase 3의 독립 최종 평가로 정상 응답 회귀 및 안전성을 확인한다. 이번 작업은 모델 재학습과 GPU 재평가를 실행하지 않았고, 기존 400건 원본 결과를 변경하지 않았다.

## 검증 결과

로컬 테스트 119개와 프로젝트 Ruff 검사를 통과했다. 원본 평가 해시 400건과 정답 판정의 응답 연결 160행을 확인했다. 보관 중인 두 AI 평가표의 원본은 변경하지 않았다. 새 코드의 모델 응답 품질과 실제 GPU 서빙은 아직 검증하지 않았으며 Phase 2 종료와 제품 공개 승인은 별개다.
