# V63 동일 장비 baseline 비교 — 지연 기준 미충족

2026-09-18, Git에 공개한 커밋 `8c9a3965ef1ec38127cf77f51fe1beb8b1a0e4bf`를 별도로 배포해 같은 RTX 3090에서 baseline과 V63을 측정했다. V63은 개발 행동 일치 **98/100**, 오류 **0건**을 재현했다. p95는 baseline의 **1.562배**로 공식 1.25배 한도를 넘었다.

## 평가 결과

| 항목 | baseline | V63 |
| --- | ---: | ---: |
| 개발 guarded 시나리오 | 100 | 100 |
| 행동 일치 | 72/100 | 98/100 |
| 실행 오류 | 0건 | 0건 |
| p50 | 0.534초 | 2.995초 |
| p95 | 3.606초 | 5.631초 |

`5.631 ÷ 3.606 = 1.561564…`이다. 현재 baseline에서 1.25배 한도는 **4.5075초**이며, V63은 이보다 **1.1235초** 길다. 약 20%의 p95 단축이 필요하다. 사용자 개발 지향값인 5.185초와 5초 미만도 이번 측정에서는 달성하지 못했다. 이 결과가 팀의 공식 기준을 변경하지는 않는다.

V63의 100개 시나리오에서 질문별 답변·행동은 [원래 V63 전체 결과](../phase3-v63-full-20260918/README.md)와 모두 같았다. 기존 p95 5.540초와 새 5.631초의 차이는 약 1.6%다. 같은 조건의 한 차례 재실행 결과이며 다른 장비나 미래 실행에서의 지연을 보장하지 않는다. 남은 행동 불일치는 `dev-078`, `dev-097`이다. 내용 안전성·정확성과 독립 검수는 여전히 별개다.

## 비교 조건

- 모델: `kakaocorp/kanana-2-3b-instruct`, 리비전 `6a5d7889964c4c590299d16e309eabab1f73f8a9`, BF16, 어댑터 없음.
- 동일 개인 RTX 3090 한 대, 동일 모델 서버를 재시작 없이 사용했다. vLLM 0.29.0, prefix caching 켬, batch invariant 켬, 동시 시퀀스 1이다.
- 공개 커밋의 같은 소스에서 `baseline`, `legacy_harm_v63` 프로필만 바꿨다. 모델·정책·데이터·공통 생성 설정 해시/값의 일치를 검증했다.
- 고정 개발 100문항, `guarded` 모드, 단계 기록 켬. 생성 384토큰·검사 80토큰, `temperature=0`, `seed=42`다.
- 각 프로필의 첫 2문항을 warmup으로 실행한 뒤 집계에서 제외했다. 본 측정은 baseline 100건 → V63 100건 순서의 단일 패스다. 역순 반복이나 통계적 신뢰구간을 계산한 결과는 아니다.
- 지연은 시나리오 전체 시간이며 다중 턴은 합산한다. 첫 토큰 지연, STT·TTS·UI 시간은 포함하지 않는다.
- 최종 독립 300문항은 사용하지 않았다. 라벨·루브릭·기존 답변을 수정하지 않았다.

## 실행 오류와 복구

첫 준비 시도는 GPU 환경에 `pip` 모듈이 없어 패키지 목록 기록에서 종료됐다. 이때 모델 호출은 0회다. `importlib.metadata`로 설치 패키지를 직접 읽도록 바꿔 별도 `attempt02`에서 실행했고, 첫 시도의 소스·로그·상태를 [attempt01 기록](results/attempt01/)에 보존했다.

수집 후 메타데이터 검증은 처음에 `generation` 객체 전체 일치를 요구해 중단됐다. V63에만 존재하는 `input_recheck_response_format=json_schema`가 baseline의 `null`과 다른 것은 예상된 프로필 차이다. 공통 생성 설정 5개는 동일한지 검사하고, 이 필드는 두 프로필의 예상값을 각각 검사하도록 분석 도구를 수정했다. 모델 재실행이나 결과 변경은 없었다.

백업 성공을 확인했으며 Pod나 모델 서버는 재시작하지 않았다.
